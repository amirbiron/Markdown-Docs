01 טיפוגרפיה וכותרות

היררכיית הכותרות היא ההסכם היחיד בין הכותב לקורא. H2 פותח נושא, H3 מחלק אותו, ו‑H4 הוא הגבול — מעבר לזה כבר צריך עמוד נפרד. טקסט שאינו רלוונטי מסומן ולא נמחק, ושמות ערכים נכתבים כ‑inline code. קישורים כמו רפרנס ה‑API תמיד מקבלים טקסט שמתאר את היעד.1

H3 — כותרת משנית

ברמה הזאת נכנסים לפרטים: מה קורה בפועל, מה נכשל, ואיך מזהים את זה. פסקה אחת לרעיון אחד.

H4 — מקרה קצה

שמור ל‑אבל אחד: התנהגות חריגה, גרסה ישנה, דגל שצריך לכבות.

DISPLAYכותרת ראשית
LEADפסקת פתיחה מובילה
BODYגוף הטקסט, 16.5px / 1.85
CAPTIONכיתוב, הערות ומטא‑דאטה

03 ציטוטים והתראות

תיעוד טוב לא מסביר מה הקוד עושה. הוא מסביר למה החלטנו שזה מה שהוא צריך לעשות.
— מתוך מדריך הסגנון הפנימי
i
מידע. בלוקי קוד נשארים LTR גם בתוך מסמך עברי — הכיוון נקבע על הבלוק, לא על העמוד.
✓
הצלחה. העמוד עבר בדיקת RTL: אין תכונה פיזית אחת בפריסה.
!
אזהרה. צלליות וגרדיאנטים לא מתהפכים לבד. אם יש להם משמעות כיוונית, הפוך אותם במפורש.
✕
שגיאה. flex-direction: row-reverse בתוך הקשר RTL מחזיר את הסדר ל‑LTR. אל תשתמש בו כדי "ליצור" RTL.
?
הערה. שדות טופס מקבלים dir="auto" כדי שכל ערך יזהה את הכיוון של עצמו.

06 רפרנס API

GET /v3/docs/{slug} שליפת מסמך בודד

מחזיר את עץ הבלוקים המרונדר יחד עם המטא‑דאטה. אם המסמך טיוטה, נדרש מפתח עם הרשאת docs:read_draft.

פרמטר טיפוס תיאור
slug חובה string מזהה המסמך בכתובת
locale "he" | "en" ברירת המחדל היא שפת הפרויקט
POST /v3/docs יצירת מסמך
DEL /v3/docs/{slug} מחיקה רכה
